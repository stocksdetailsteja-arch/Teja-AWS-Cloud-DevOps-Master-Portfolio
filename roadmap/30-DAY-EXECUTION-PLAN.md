# 🗓️ 30-Day Execution Plan

| Day | Focus | Concepts | Production outcome |
|---:|---|---|---|
| 01 | **Linux Foundation I** | filesystem, navigation, files, users, groups and permissions | Build a system baseline and permission laboratory |
| 02 | **Linux Foundation II** | processes, signals, systemd, journald, cron, packages and disks | Operate, break and recover a Linux service |
| 03 | **Networking** | CIDR, subnetting, DNS, TCP, TLS, HTTP, routing and firewalls | Trace and repair a complete request path |
| 04 | **Git & GitHub** | objects, branches, merge, rebase, conflicts, recovery and PR workflow | Recover from conflicts and publish a reviewed branch |
| 05 | **Bash & Python** | safe scripting, jq, APIs, retries, tests and idempotency | Create health, backup and inventory automation |
| 06 | **AWS & IAM** | regions, accounts, roles, policies, STS, audit and budget protection | Validate role identity and least-privilege behavior |
| 07 | **EC2, EBS & SSM** | compute lifecycle, AMI, storage, metadata and secure operations | Deploy and recover an EC2 workload |
| 08 | **VPC I** | CIDR, subnets, routes, IGW, SG and NACL | Build a two-AZ network foundation |
| 09 | **VPC II** | NAT, endpoints, DNS, ALB and VPC traffic evidence | Operate private workloads and diagnose reachability |
| 10 | **S3 & CloudFront** | encryption, versioning, lifecycle, policies and delivery | Build secure object delivery and recovery |
| 11 | **RDS & DynamoDB** | relational/NoSQL selection, availability, backup and access | Build a private data tier and recovery plan |
| 12 | **ALB & Auto Scaling** | health checks, launch templates, policies and resilience | Build a horizontally scalable application tier |
| 13 | **AWS Operations** | CloudWatch, CloudTrail, Config, SSM and event automation | Detect, alert and investigate a cloud incident |
| 14 | **AWS Integration Project** | secure multi-AZ application architecture | Complete failure game day and teardown |
| 15 | **Terraform Fundamentals** | HCL, provider, resources, variables, outputs and lifecycle | Rebuild AWS foundation as code |
| 16 | **Terraform Production** | modules, remote state, locking, import, drift and tests | Create reusable modules and recovery procedures |
| 17 | **Docker** | images, layers, multi-stage builds, networking and Compose | Containerize and secure the application |
| 18 | **CI/CD** | GitHub Actions, Jenkins, artifacts, security gates and deployment | Deliver an immutable image through a controlled pipeline |
| 19 | **Kubernetes I** | architecture, Pods, Deployments, Services and rollout | Deploy, inspect, scale and roll back workload |
| 20 | **Kubernetes II** | probes, config, secrets, storage, RBAC and NetworkPolicy | Harden and troubleshoot the workload |
| 21 | **EKS, ECR & Helm** | managed Kubernetes, registry, charts and releases | Deliver charted workload to AWS |
| 22 | **Ansible** | inventory, playbooks, roles, templates and idempotency | Configure systems through repeatable automation |
| 23 | **Metrics & Alerts** | Prometheus, Grafana, RED/USE and SLO signals | Create actionable dashboard and alert |
| 24 | **Logs & Traces** | structured logs, correlation and OpenTelemetry | Build an incident timeline across components |
| 25 | **DevSecOps** | secrets, SAST, SCA, IaC/image scans, SBOM and policy | Reject an intentionally unsafe change |
| 26 | **Argo CD** | GitOps reconciliation, drift, promotion and rollback | Detect drift and restore desired state |
| 27 | **SRE & Incident Response** | SLOs, error budgets, runbooks and incident command | Conduct a controlled outage and post-incident review |
| 28 | **DR & FinOps** | RTO/RPO, backup restore, budgets, tags and teardown | Exercise recovery and prove cost cleanup |
| 29 | **Production Capstone** | full integration, hardening and acceptance tests | Complete architecture, recovery and portfolio evidence |
| 30 | **Interview & Portfolio** | mock rounds, project narrative, resume evidence and audit | Explain the system from Linux to business outcome |

## Completion rule

A day is complete only after implementation, validation, controlled failure, evidence-based diagnosis, recovery, security review, cost cleanup, interview answers, screenshots and a clean Git commit.
